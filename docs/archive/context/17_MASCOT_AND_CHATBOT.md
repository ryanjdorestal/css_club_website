## The mascot

John Jay College's athletics mascot is the **Bloodhound**. The club's YouTube banner
(`../jjay_css_refs/club/youtube_banner.png`, left side) shows it: a white/light-gray bloodhound
head-and-shoulders, long droopy ears, jowls, wearing a **navy knit beanie**, drawn in a
clean flat-vector style with navy outlines, on the banner's steel-navy `#1E4664`.
That drawing is the reference. It is the college's mark; a recognized student club using
its own college's mascot is normal — keep it respectful, don't alter it into something
the college wouldn't sign off on.

## What to build

`apps/web/src/mascot/` — an SVG bloodhound head as a React component with an `emote`
prop, matching the banner's style (flat vector, navy line, beanie, light fur, teal `#6ED2E6`
highlights where the banner uses its ring glow):

| emote | when |
|---|---|
| `idle` | default; slow blink every ~6s |
| `thinking` | while a question is being answered (ear tilt, eyes up) |
| `happy` | answer found with citations |
| `confused` | no KB match ("try asking about events, joining, apps…") |
| `sleeping` | API offline (Tier-1 fallback state) — z's in VT323 |
| `alert` | new bulletin / unread |

Also export a 32px static version for the chat launcher button and a 512px PNG for
social/OG. Keep the SVG under ~12 KB; animate with CSS/Motion, not GIFs.

Process: trace the banner's bloodhound by eye into clean paths (do not embed the raster),
match proportions (ear length ≈ head height, beanie sits low), then derive the emotes by
swapping eye/brow/ear groups. Screenshot each emote at 64/128/256 px into `qa/shots/`.

## The chatbot ("Hound")

Port of rhecwb's `chat-assistant` **to Python, no LLM, no keys**:

- `GET /api/chat` → `{ ok, source: "static", configured: false, mascot: "bloodhound" }`
  so the UI can show a status pill without any call chain.
- `POST /api/chat { message, page? }` → `{ ok, source: "static", answer, suggestions[],
  citations[], emote }`.
- Matching: normalized keywords + simple stemming + page context boost; ties broken by KB
  order. Return `emote` so the widget picks the face.
- KB: `data/kb.json` — public-safe entries only (join, events, apps, cyberhounds, discord,
  resources, board, about, hours/room, email). Built from the migrated old-site copy plus
  `site_settings`. Regenerated by `scripts/build_kb.py`. Never board/operator internals.
- Fallback: when the API is unreachable the widget answers from a bundled copy of the KB
  in the client (`sleeping` emote + "answering offline"). The site never shows a dead chat.
- Rate-limit by IP in memory (Vercel function) — cheap; no store needed.

UI: launcher = the 32px Bloodhound in the bottom-right, teal ring on hover; panel = dark
navy, mono kicker `// HOUND · STATIC`, suggestions as chips, citations as links.
